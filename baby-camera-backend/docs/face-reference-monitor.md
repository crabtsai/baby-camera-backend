# 本機臉部參考監測

這是實驗性的「外觀改變／追蹤失效」提醒，不是已驗證的棉被遮擋分類器，也不能證明口鼻暢通。

2026-10-26 本機實拍測試：床位攝影機在原方向下人體模型未檢出人物，逆時針 90 度後檢出一人。MediaPipe 在完整畫面未找到臉，使用人體頭部區域裁切後能定位鼻子與嘴唇。這只是單張成功，不能當成準確率或夜間可靠性驗證。照片只留在忽略版控的本機資料夾，未送到外部服務。

## 流程

1. 畫質檢查、人體定位與連續在床判斷。每次由未偵測到人物轉為持續出現人物時保存照片，最短間隔五分鐘；模型不辨識寶寶身分，照顧者也可能觸發。
2. `pose_rotation` 僅校正人體模型輸入；所有輸出座標轉回原畫面，串流及存檔維持原方向。
3. 裁切並擴大頭部區域，讓 MediaPipe 定位口鼻。沒有頭部區域時仍嘗試完整畫面。
4. `reference_monitor=true` 時，連續三張位置穩定的臉建立記憶體參考，並保存本機參考照片。這不代表參考畫面已確認安全。
5. 臉部灰階外觀正規化後比較全臉及鼻／嘴局部，差異超過門檻，或已建立參考後臉部定位消失，產生提醒候選。持續五秒才建立事件、保存事件照片並觸發監看頁面聲音；事件冷卻三分鐘。
6. 缺幀超過允許間隔會打斷警報累積時間。異常期間不自動覆寫參考，避免把遮擋學成正常；重啟監測程式可重新建立參考。

轉頭、光線、表情、照顧者進入畫面、移動鏡頭也可能造成提醒。若首次就遮住臉而無法建立參考，這項比對不會啟動，介面會顯示等待建立參考。不能用它取代照顧者查看。

## 設定範例

```ini
[camera.bed-camera.detectors.safety]
enabled = true
pose_rotation = 90
reference_monitor = true
sleep_region = 0.05,0.05,0.95,0.95

[camera.bed-camera.detectors.face_parts]
enabled = true
```

`sleep_region` 必須按自己的床位校準，以上只是範例。參考照片、人物出現照片及事件照片在既有 `snapshot_dir` 下依相機分開保存；`/health` 的 `presence_snapshot`、`reference_snapshot` 提供最新路徑。這些照片不會自動刪除，使用者需按自己的保留需求清理。現有本機模式仍不自動發送外部通知。瀏覽器必須啟用聲音並維持開啟；攝影機喇叭尚未整合。

## 物件辨識仍需什麼

既有 `head_obstruction_warning` 在設定的異物模型可用時，以物件框和頭部區域重疊提醒，現在也會觸發本機聲音。沒有異物模型時明確標示無法判讀；外觀差異不會被標成「已辨識棉被」。單張參考照片不能自動訓練出可靠的所有物件辨識。

較值得驗證的方向是專用棉被／枕頭實例分割、頭部／口鼻定位以及時間追蹤結合，使用輪廓交集減少大矩形框的誤報。尚需代表實際鏡位、日夜、轉頭、奶嘴與遮擋的標註資料及獨立測試，才能比較漏報、誤報和延遲。目前不宣稱哪個模型在這台攝影機上最穩定。

來源：
- Google [Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker)：輸出臉部關鍵點，不輸出棉被分類或口鼻可見性證明。
- [CribNet / CribHD](https://github.com/ostadabbas/CribNet)：床內棉被與玩具偵測、分割及遮擋研究；研究數據不等於本機驗證結果。

驗證採合成影像、既有本機照片與離線重播，勿為測試警報而遮住寶寶口鼻。
